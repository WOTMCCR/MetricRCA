## What Failed

### Failure 1: Missing LLM Provider/Model

First Eval Agent command omitted:

```text
METRIC_RCA_LLM_PROVIDER=openai
METRIC_RCA_LLM_MODEL=gpt-5-nano
```

The eval aborted at the first memory prepass case:

```json
{"error_code":"LLM_REQUIRED_UNAVAILABLE","message":"LLM_REQUIRED_UNAVAILABLE: round-01-mem-gmv_paid_ads_drop-r3"}
```

Root cause:

- `OPENAI_API_KEY` only fills `llm_api_key`.
- It does not set `llm_provider` or `llm_model`.
- `MetricService._get_intent_planner()` requires explicit provider/model.

Lesson:

- Always set provider/model for eval commands.
- Do not disable LLM or memory to bypass this; that would violate the required runtime path.

### Failure 2: Reusing Same Eval ID After Failed Start

Second Eval Agent set provider/model but reused `--eval-id round-01`.
The first failed attempt had already inserted failed `agent_run` rows:

```text
round-01-mem-gmv_paid_ads_drop
round-01-mem-gmv_paid_ads_drop-r2
round-01-mem-gmv_paid_ads_drop-r3
```

Rerunning the same eval id tried to `start_run()` with the same run id but expected `status=running`; existing row had `status=failed`.
The repository idempotency check correctly rejected this and surfaced:

```json
{"error_code":"SYSTEM_TABLE_WRITE_FAILED","message":"SYSTEM_TABLE_WRITE_FAILED: round-01-mem-gmv_paid_ads_drop"}
```

Resolution already done:

- Reseeded with `ALLOW_DESTRUCTIVE_SEED=true`.
- System tables are now clean.

Lesson:

- After a failed eval that inserted `agent_run` rows, either reseed before rerunning the same `eval_id`, or use a new `eval_id`/cycle.
- For PTV artifact consistency, deterministic reseed is preferred before rerunning the same round.
